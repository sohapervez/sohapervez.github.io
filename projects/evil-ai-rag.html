The Problem

AI-safety researchers work with large corpora of dense, technical PDFs. Standard keyword search returns too many irrelevant results; generic chatbots hallucinate citations and fabricate details. There was no reliable way to ask a question across a library of papers and get a grounded, cited answer.

What I Built

A full Retrieval-Augmented Generation pipeline that turns a folder of research PDFs into a queryable knowledge base:

  • PDF ingestion — PyMuPDF with layout-aware extraction
  • Parent-child chunking — section detection preserves context hierarchy
  • Embeddings — BAAI/bge-base-en-v1.5 (768-dimensional) into two ChromaDB collections
  • Hybrid retrieval — vector similarity + BM25 keyword matching combined
  • Cross-encoder reranking — refines the candidate list before the LLM sees it
  • Multi-provider LLM — works with Ollama, OpenAI, Anthropic, and Groq via env config
  • API layer — FastAPI with authenticated endpoints for chat streaming, paper management, analytics, and CSV export
  • UI — Streamlit front-end; also integrated as a chatbot on the EVIL AI website
  • Deployment — Docker Compose for local dev; Kubernetes manifests for OpenShift / Rahti

The Result

Cited, grounded answers across large paper collections.

The system is deployed on OpenShift and integrated directly into the EVIL AI website as a live chatbot. Users upload their own PDFs or query the existing corpus and receive answers with source citations — no hallucinated references. Fine-grained retrieval parameters and chunking strategies are tunable via environment variables without redeployment.
