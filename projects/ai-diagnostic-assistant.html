Educational purposes only. This tool is not a substitute for professional medical advice, diagnosis, or treatment. Always consult a qualified healthcare provider.

The Problem

People often struggle to articulate symptoms clearly and don't know what follow-up information a doctor would need. A structured, conversational tool that asks the right questions could help users prepare for appointments and understand possible causes — while being clear about its limitations.

What I Built

A Streamlit chatbot built from scratch in 24 hours, with no prior RAG experience. The app follows a structured diagnostic conversation flow:

  • Symptom intake — user describes their primary complaint in free text
  • RAG retrieval — LangChain queries a ChromaDB vector store built from a medical symptoms CSV knowledge base
  • Sequential follow-up — the LLM generates 3–5 targeted follow-up questions, presented one at a time
  • Differential diagnosis — after gathering responses, the model produces a likely diagnosis with a supporting explanation
  • Session reset — users can start a fresh consultation at any time

All LLM calls go through the OpenAI API via LangChain; the knowledge base is built from a local symptoms_data.csv on first run.

The Result

A fully working symptom-assessment chatbot delivered in one day, starting from zero knowledge of RAG architecture. The 24-hour timeline demonstrated that a functional, grounded LLM application can be built quickly once the underlying retrieval pipeline is understood — a proof of concept in rapid AI prototyping.
